## dsh-chatnode-wechat v0.3.1

自 v0.3.0 以来的改进。

### 修复

- **`/早安 test` 只回一句 `fetch failed`，天气推送被本地代理卡死**：`fetch` 把任何传输层失败都报成 `TypeError: fetch failed`，真实原因（`ENOTFOUND` / `ECONNREFUSED` / TLS / 超时）藏在 `error.cause` 里 —— 代理活着但不放行 `api.open-meteo.com` 时，与真的断网完全无法区分
  - 失败信息现在会展开 cause 链（含 happy-eyeballs 的 `AggregateError`）并写出真实原因
  - 天气请求在传输层失败后会改用 `node:https` **直连重试一次**（`agent: false`，不经过任何代理 dispatcher）才放弃；两次都失败时同时给出两条原因与代理排查提示
- **裸 `1` / `2` 回答权限请求失效**：命令路由在判断「是否以 `/` 开头」时就把数字挡掉了，`resolveApproval()` 根本收不到 `1` / `2` —— 数字被当成聊天内容喂给模型，审批只能等超时
  - 审批回复（`/yes` `/no` 与裸 `1` / `2`）现在先于斜杠判断处理；没有待确认请求时 `1` / `2` 仍会交回给 `/model` `/perm` 菜单与模型
- **`/yes` `/no` 在没有待确认请求时**：以前回「❓ 未知命令 /yes」并附上整段帮助（读起来像是命令坏了），现在明确回一句「当前没有待确认的请求」
- **老灯控命令失效**：已退休的 `dsh-wechat-tools` 插件用的是设备自己的词表（`/gear` `/off` `/low` `/mid` `/high`），此前一律回「未知命令」
  - 五个拼写已恢复（`/gear` 查档位，其余对应 关 / 低 / 中 / 高），与 `/开灯` 系列共用同一份实现，`/help` 一并列出
- **灯控同样被代理影响、报错只有 `fetch failed`**：局域网设备请求现在也会在传输层失败后直连重试，报错同样带出真实原因

- **`/perm` 一声不响**：权限预设是**会话级**服务（`current(session)` / `set(session, name)`，标签来自 `optionOf()`），而桥按「传事件数组」的旧假设调用 —— 抛出的异常逃出命令路由、被入站处理器吞掉，于是 `/perm` 完全没有回复，与「桥挂了」无法区分
  - 现在按宿主真实签名调用，整段调用都有保护：宿主 API 变化时至少回一句失败原因
- **命令面整体改为「绝不静默」**：`/perm` `/model` `/sessions` `/status` `/send` 任一步骤抛错都会回一句 `❌ …失败：<真实原因>`，不再出现「发了没反应」；`/send` 也改成 `ctx.get('wechat')` 取服务（与 v0.3.0 的服务访问规范一致）
- **重启后 `/sessions` 与 `/status` 显示「没有会话」**：内存中的会话要等第一条聊天消息才会恢复；两个命令现在会先尝试恢复持久化的 `wechat-` 会话再作答

### 其它

- 单元测试 **143 → 158 项**（新增 `commands` 11、`morning` +3、`light` +1；「设备不可达」用例改为同时注入直连传输，测试不再触网）
- 新增 `src/node/net.ts`：`describeError()` 与 `directRequest()` 供天气与灯控共用，避免两处各写一遍
- 文档：中英首页加「代理排查」提示；`DEVELOPMENT.md` 环境约束补记该坑与通用做法

仅供参考，已在一套环境实测（2026-09）。拉取后需 `pnpm build` 并**重启 dsh web** 才会加载新的命令与网络兜底。
