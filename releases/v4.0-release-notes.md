## dsh-wechat-suite v4.0

> 名字说明：仓库叫 `dsh-wechat-suite`，安装的包叫 `@dsh-cowork/chatnode-wechat`，
> 在 profile 里配置时写的插件 id 是 `dsh-chatnode-wechat` —— 三个名字指同一个东西：
> 安装命令用仓库名，配置文件里写插件 id。

**一次大版本。** 上下文管理、Web 管理台、长期记忆三块重做；桥从"会回话"变成
"记得住、说得清、坏了有痕迹"。

- **上下文管理大改** —— 不再靠"到点换对话"续命，改成 **一个会话到底 + 分层记忆**；
  压缩参数显式化，并把"刚说过的话绝不能被吞掉"这件事钉在配置里。
- **Web 管理台重写** —— **新手模式 / 高级模式**双模式：不熟配置的人只看见必须填的几项、
  全程大白话；专业用户拿到全部字段、诊断与备份回滚。UI 重做为克制的工具面板。
- **长期记忆（新）** —— `MEMORY.md` 跨会话事实文件 + 每天自动整理 + `remember_fact`
  工具（说"记一下"立刻落盘），换会话、换模型、重启都带着。
- **问题台账（新）** —— 每一次被吞掉的失败都写一行日志、进 `/problems`、
  `/status` 显示网关健康；告警限流，不会变成刷屏。
- 一并修掉几个**真问题**，其中最严重的一个让 `send_email` 一直报"SMTP 未配置"，
  而配置其实一直是对的。

---

### 一、上下文管理：把"一个会话到底"真正做实

v0.3.x 就已经把默认方案设成 `manual`（不自动轮换），但**默认值不等于体验**：那时候既没有
任何地方能看出上下文到底用了多少，也没有任何地方能看出宿主的压缩在什么时候触发、
会保留什么。v4.0 把这条路线做实，桥在两侧补齐四件事（默认值本身没变，仍是 `manual`）：

- **`/context` 命令（新）**：把宿主自己测出来的数字摊开说清楚 ——
  当前占用 / 模型窗口 / 组成（对话·工具·系统）/ 压缩触发点 / 压缩后原样保留多少 /
  长期记忆条数。数字来自宿主的会话投影缓存，不是估算。
- **压缩参数显式化（建议显式写出）**：`dsh-compaction-basic` 默认
  `thresholdRatio 0.8 / retainRatio 0.16`。建议在 agent preset 里写死成：

  ```yaml
  - id: compaction-basic
    name: '@deepseek-ai/dsh-compaction-basic'
    config:
      auto: true
      thresholdRatio: 0.65
      retainRatio: 0.25
      maxTokens: 8192
      compactionRetries: 1
      maxOverflowRetries: 1
  ```

  原因：宿主的**溢出恢复**路径把 `retainTokens` 硬编码为 0 —— 那条路只保留最后一条
  消息，正是"刚说完就被忘掉"。提前到 65% 触发，就永远走不到那条路上；保留 25%
  （100 万窗口的模型＝25 万 token 逐字保留）意味着普通对话**整段都在原样尾巴里**。
- **压缩后自动重新注入记忆**：压缩发生在回合中间（每个 step 之前），桥监听
  `compaction/summary`，让用户的下一条消息重新带上完整长期记忆，而不是等下一个注入周期。
- 会话轮换方案仍然完整保留（`rotate-turns` / `rotate-pressure` / `rotate-tokens` / `daily`），
  谁需要谁自己切 —— 它们只是继续处在默认值之外。

### 二、长期记忆（新）

一个 Markdown 事实文件，五个小节：`关于主人`（本桥对使用者的固定称呼，写死在文件格式里）/
偏好与习惯 / 常用设备与环境 / 待办与承诺 / 重要决定（外加一个作废台账）。

- **注入方式**：作为**背景资料**贴在用户消息围栏**外面** —— 人设的硬规则是"只有围栏里的
  才算用户发言"，所以记忆永远不会被当成命令。记忆没有内容时**不注入**（空骨架只是噪音，
  还会诱导模型编内容）。
- **每天整理一次**（默认 04:30）：只从围栏里的用户原话提取事实，用会话自己的模型；
  要求距最后一条消息 2 小时以上、当天至少 5 句用户发言，否则跳过（不花冤枉钱）。
  模型输出走严格 JSON，写入按"精确匹配 + 备份 + 4000 字上限 + 审计日志"落地。
- **`remember_fact` 工具（新）**：用户说"记一下…"时模型**真的能写进去**，
  而不是嘴上说"记下了"。支持 `replaces` 取代旧事实（用户说"我换城市了"，旧的"用户在 A 城"
  就会退场，而不是两条互相矛盾的事实长期并存），
  写不进去会明确回 `❌` + 真实原因，绝不返回成功。
- **`/memory`** 查看当前记忆；`/memory now` 立刻整理一次。

### 三、Web 管理台重写

`/` 打开就是新页面，左上角切换模式：

- **新手模式**：只有必须懂的几项，全部大白话 ——
  "谁能跟我说话"（白名单，并说明不知道 ID 时怎么问它）、"用哪个大脑"（模型下拉，
  从 `settings.yaml` 读真实列表）、"它记不记得住"、"聊久了怎么办"（两个选择），
  外加一页"出问题了"（把日志原文摊出来）。
- **高级模式**：全部 36 个配置键（分组）、provider 与图片路由、记忆/问题日志路径、
  6 种上下文方案 + 参数微调 + 原始 JSON、对话与转录、配置备份与**一键回滚**。
- **8 项体检**：一行结论 + 每项失败都带"怎么解决"，而不是只告诉你哪里不对。
- **UI 重做**：深色、1px 细线、等宽数值、微标签，克制、信息密度高、有工具感；
  保存条会说清"将修改哪几项"，高级模式保存前二次确认（这个 profile 是热重载）。

新增接口：`/api/health`、`/api/problems`、`/api/memory`、`/api/models`、
`/api/backups`、`/api/rollback`。

管理台本身也修了几个安全问题：

- **写操作的第二个因子以前是死代码**：`x-wechat-admin` 守卫头在两条 token 分支之后才判断，
  永远不可达。现在带合法 token 但不带守卫头的写请求会被 403 拒绝。
- **读不出来的配置文件不再被覆盖**：以前 patch 读失败会显示成空配置，一保存就从零重写，
  把别的插件条目一起带走。现在拒绝写入并在页面上写明原因。
- **备份按时间保留最近 5 份**（以前按文件名字符串排序，删掉的可能反而是新的）。
- 数字字段服务端二次校验：把 `25 分钟` 写进整数字段会让插件加载失败、整个 profile 起不来。

### 四、问题台账：一切失败都留痕

以前的原则是"绝不把异常抛给宿主"，实现却是"返回 undefined 且一个字不说" ——
用户在微信那头看到的现象是"它不理我了"，而日志里什么都没有。

现在每次被吞掉的失败都会：

- 写一行到 `$DSH_HOME\wechat-problems.log`（**256KB 自动轮转**，写不进去也不会再抛）；
- 进内存台账，`/problems` 可查、`/problems clear` 可清；
- **在微信里主动说明一次** —— 同一问题 10 分钟内只提醒一次、每小时最多 6 条，
  留痕不等于刷屏；
- `/status` 多一行**网关健康**（在线 / 重连中 / 暂停 / 已停止），
  以前网关死了和"今天没人说话"长得一模一样。

接了台账的路径包括：入站处理、网关 status/error/fatal、出站分块失败、**整轮空回复**、
切会话后被丢弃的回复、早安推送失败、提醒读写与投递、记忆的种子/状态/LLM 失败、
生图路由探测、管理台队列、上下文方案 JSON 损坏、会话恢复失败、OCR 与语音转写失败。

### 五、修掉的真问题

- **配置被宿主静默丢弃（最严重）** —— 宿主用 bundle 的 schema 校验 profile patch，
  再转发给会话节点；而 `smtpHost / smtpPort / smtpUsername / smtpPassword / smtpFromName`
  **只声明在节点侧**，宿主校验时直接丢掉。后果：`send_email` 永远回
  "SMTP 未配置"，哪怕 patch 里五项齐全、凭据也完全可用（已用 TLS + AUTH LOGIN 实测）。
  同样被丢的还有 `imageInput` / `imageInputModel`（图片输入模式永远不生效），
  以及 12 个网关键（`sendChunkRetries`、`allowCdnHosts` 等——改了等于没改，完全无声）。
  现在四份键集（bundle schema / 转发 / 节点 schema / 管理台字段）**必须相等**，
  并有 `config-surface` 测试守护：加新配置键忘了改一处，测试直接红。
- **模型替用户写话** —— 长对话里模型开始复读"用户消息"的围栏格式、自己编出用户的下一句
  并作答，整段原样发到了微信。人设里写着禁止，但规则挡不住格式惯性。现在出站前
  **确定性裁掉**围栏及其之后的一切（代码块里的引用不误伤），并记 `model/echo`。
- **假警报** —— 工具调用步骤（查天气那一步）本来就没有文本，旧代码把它当成
  "模型返回空内容"并主动向用户发出 ⚠️。现在按**整轮**判定：整轮一个字都没产出才算问题。
- **其它**：切会话后心跳定时器永不停止（每次切换漏一个，永远推"仍在处理中"）；
  热重载不 abort 在途长轮询，与同 token 的新实例重叠会被 iLink 判 403 导致新桥停摆；
  早安/提醒定时器在时钟异常时 NaN → 立即触发 → 重新武装（忙循环）；
  提醒文件读坏被当成空列表并在下次保存时覆盖；
  插件卸载时未决审批永久悬挂；`net.ts` 响应流缺 `error` 监听（进程级崩溃隐患）。

### 六、升级与兼容

```sh
# 从零安装
dsh plugin --profile <profile> add github:PRTS168/dsh-wechat-suite
# 升级到 v4.0（同一命令，重装即升级）
dsh plugin --profile <profile> add github:PRTS168/dsh-wechat-suite
```

- **配置向后兼容**：v4.0 新增的键都有默认值（记忆在 `$DSH_HOME\wechat-memory\`，
  问题日志在 `$DSH_HOME\wechat-problems.log`），旧配置不改也能跑 —— **除了下面这条灯控地址**。
- **行为变化（会打到已有安装）**：灯控**不再内置默认地址**。旧版本在 `light.ts` 里硬编码了
  一个具体的局域网地址，那是某个人的环境数据，不该随仓库分发（也是本次脱敏的一部分）。
  升级后请在 profile 里补一行 `esp32BaseUrl: "http://<esp32-ip>:80"`（或管理台 → 高级模式 →
  可选），否则 `/开灯` 与 `control_esp32_light` 会明确回"灯控还没配置"并给出填法 ——
  不会静默失败，但不补就真的开不了灯。
- **行为变化**：上下文方案默认值与 v0.3.x 相同（`manual`），但**建议按第一节把
  compaction 参数显式写出**，否则跑的是宿主默认的 0.8/0.16。
- **新命令**：`/context`、`/problems`、`/memory`（`/memory now`）。
- **新工具**：`remember_fact`。
- 需要 DSH `0.1.2-rc.1`（桌面版）或 `0.1.5-rc.2`（CLI），Node ≥ 22。
- 仍不支持的：群聊、朋友圈、主动发消息给非白名单联系人（白名单是硬闸门）。

### 七、验证

- **255 项离线单元测试**（v0.3.1 为 167 项），全部在临时目录里跑，不触网、不需要微信。
- 新增测试：`config-surface`（配置面键集一致性）、`problems`（台账/限流/轮转）、
  `robustness`（拒写、原子写、备份裁剪、日志轮转）、`context-report`、`memory`、
  `outbound-guard`（用真实事故原文做用例）、`packaging`（发布包白名单不得扫进 token 与日志）。
- 外部依赖实测（维护者环境跑通一次，仅供参考）：SiliconFlow Key 可用且 4 个配置的模型 id
  都存在；SMTP `465` 端口 TLS + 登录成功；ESP32 灯 `HTTP 200`；Open-Meteo 可用；
  iLink 网关可达。
