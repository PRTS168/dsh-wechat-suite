## dsh-wechat-suite v4.1

**一个小版本，治"卡"。** 网关传输层加固、长回合不再长时间静默；另外把 v4.0 漏写的一条
破坏性变更补进文档 —— **从 v0.3.x 直接升上来的人务必看「升级与兼容」**。

- **传输层故障能自愈** —— 连接层出问题时，后续请求自动改走全新连接，不必再重启进程才能恢复。
- **长轮询窗口有了上限** —— 服务端建议的窗口不再能无限顶掉你的配置，且两个数字都会写进日志。
- **长回合第一条进度提前到约 20 秒** —— 原来要等满 5 分钟，那五分钟里"慢"和"卡死"没有区别。
- 修掉一条在 Linux CI 上必红的测试；补齐灯控地址的破坏性变更说明。

---

### 一、网关传输层：从"卡死 18 分钟"到能自愈

2026-09-13 16:15–16:33，本桥连续 18 分钟发不出任何消息：问题台账里 108 条 `[gateway]`，
同一个错误重复 96 次（告警限流生效，只打扰了使用者一次），最后靠重启 DSH 才恢复。

那次故障的指纹很明确，也是这次修复的依据：

- **每一个**请求都以同样方式失败：`fetch failed / invalid content-length header / UND_ERR_INVALID_ARG`；
- 进程内重试 96 次，无一例外；
- 而**重启进程瞬间恢复**。

这不是网络断了 —— 重启修不好真正的断网 —— 而是**进程级连接状态中毒**：undici 的连接池在
网络/代理抖动之后整体失效，此后每次复用都是同一个坏结果。所以修复做成"换路"：

- 传输失败之后，**下一次请求改走全新连接**（`node:http(s)` 且 `agent: false`：不经连接池，
  也不受宿主全局 dispatcher 影响）；一旦成功就回到常规路径；切换时宿主日志写一行。
- 为什么不"立刻重发"：iLink 发送不保证幂等，重发会让你收到重复气泡。换路只影响后续请求。
- 顺带验证过这**不是**"我们构造请求有问题"：中文 / emoji / 孤立代理对 / 500KB 等 8 组用例，
  `Content-Length` 与实际字节数全部一致。

### 二、长轮询窗口有了上限

`longpolling_timeout_ms` 是服务端建议的长轮询时长。v4.0 及以前，它会**无上限地顶掉**配置值。
如果服务端是"窗口到期才回"，那这个窗口**就是**"按下发送 → 桥看见消息"的延迟。

现在取 `min(服务端建议, longPollTimeoutMs)`，并把两个数字一起写进日志
（`long poll window: … (server suggested …)`）。觉得取件不够快，把 `longPollTimeoutMs` 调小即可
（例如 `15000`，代价是轮询频率变高）。

### 三、长回合不再长时间静默

心跳原来要等满 `digestIntervalSec`（默认 **300 秒**）才发第一条：长回合里就是五分钟鸦雀无声，
"慢"和"卡死"因此无法区分。现在第一条约 **20 秒**就发出，之后按原间隔；排程改为显式可取消，
回合结束后绝不会再推"仍在处理中"。

### 四、修掉的问题

- **Linux CI 一直红**：`robustness` 里"配置文件读不出来时拒绝写入"这条用例，`chmod 000`
  之后没恢复权限就回读，测试自己吃 `EACCES`（Windows 不强制权限位，所以本地一直全绿）——
  v4.0 起连续三次推送的 CI 都是红的。
- **灯控的破坏性变更此前没写进文档**（见下一条），升级的人会静默失去灯控。

### 五、升级与兼容

```sh
# 从零安装 / 升级到 v4.1（同一命令，重装即升级）
dsh plugin --profile <profile> add github:PRTS168/dsh-wechat-suite
```

- **必读（从 v0.3.x 升上来的）**：灯控**不再有内置默认地址**。旧版本在 `light.ts` 里硬编码了
  一个具体的局域网地址 —— 那是某个人的环境数据，不该随仓库分发（v4.0 已移除）。请在 profile 里
  补一行 `esp32BaseUrl: "http://<esp32-ip>:80"`（或管理台 → 高级模式 → 可选），否则 `/开灯` 会明确
  回"灯控还没配置"并给出填法 —— 不会静默失败，但不补就真的开不了灯。
- 其余配置向后兼容：v4.0 / v4.1 新增的键都有默认值，旧配置不改也能跑。
- 上下文方案默认值仍是 `manual`（与 v0.3.x 相同）。
- 需要 DSH `0.1.2-rc.1`（桌面版）或 `0.1.5-rc.2`（CLI），Node ≥ 22。

### 六、验证

- **261 项离线单元测试**（v4.0 为 255 项），全部在临时目录里跑，不触网、不需要微信。
- 新增用例：`gateway-transport`（传输失败换路、成功后回池、HTTP 错误不算传输失败、窗口封顶），
  以及进度排程的"提前发出"与"取消后不再发"。
- 实测数据（本机 48 轮真实对话的事件时间戳）：模型首字中位 **1.7 秒**、整轮中位 **1.9 秒**。
  说明：入站报文里没有服务端时间戳，所以"按下发送 → 桥收到"这一段目前只能靠长轮询窗口来约束 ——
  给它加上限正是这次的改进之一。
