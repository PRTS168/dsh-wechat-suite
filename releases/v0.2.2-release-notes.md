# v0.2.2 — 适配 DeepSeek 4.1 多模态：微信里的图片，模型自己看

**亮点：DeepSeek 4.1 的多模态能力接进来了。** 微信收到的图片现在以真正的
`image` 内容块投给模型，模型自己看图；不再只能拿到 OCR 文本。OCR 没有被删掉，
而是变成可切换的回落路径。

- 版本：`v0.2.2`
- 测试：**86 项离线单测全绿**（v0.2.1 为 72）
- 仓库：<https://github.com/PRTS168/dsh-wechat-suite>

---

## 核心改进

### 1. 原生图片输入，与 OCR 可切换（适配 DeepSeek 4.1）

入站图片有两种送达方式，由**路由模型自己声明的模态**决定：

| 模式 | 模型拿到什么 | 何时使用 |
|---|---|---|
| `native` | 真正的 `image` 内容块，模型自己看图 | 路由模型声明了图片输入 |
| `ocr` | `【OCR 识别结果】` 文本 + 文件路径 | 路由模型是纯文本 |

- `imageInput: auto`（默认）读 `llm.listModels()` 的 `inputModalities`：
  声明了 `image` 就发图片块，没声明就回落 OCR。若聊天路由是纯文本，`auto`
  还会在其他已注册路由里找声明了 `image` 的模型。
- `imageInputModel` 可以把「只用于图片」的路由钉到另一个模型——文字走便宜的、
  图片走视觉模型。
- 新增 **`/识图`** 命令，聊天内运行时切换：

  ```
  /识图            # 报告当前模式 + 当前生效的路由模型
  /识图 native     # 强制原生图片块
  /识图 ocr        # 强制 OCR 文字
  ```

- **两种模式都保留 `[微信图片] <路径>` 前缀**：会话日志可重放，模型之后还能重读该文件。

### 2. 「声明」才是开关（重要，容易踩）

harness 在**请求发出的上游**就按模型声明的 `inputModalities` 闸门拦图片——
声明成纯文本，图片根本不会被发送。而 DeepSeek 适配器内置的模型目录**早于
4.1 多模态**：它把 `deepseek-v4-flash` 记为纯文本，唯一声明了 `image` 的
`deepseek-v4-flash-vision-exp` 又已下线。

所以要在 DSH 的 `settings.yaml` 里声明：

```yaml
llm-deepseek:
  models:
    - id: deepseek-flash
      inputModalities: [text, image]
```

⚠️ 这个 `models:` 列表是**整体替换**插件内置目录、不是追加。所以要把你实际
路由到的每个 id 都列上（本项目的微信 profile 钉的是旧别名
`deepseek-v4-flash`，漏掉它那条路由就不再解析）。

**观测到的拒绝会被记住。** 「声明」只是对端点的声称、不是检验，因此某个路由
真的拒了一次图片后，会被抑制 3 小时，后续图片直接走 OCR，不再每张图都烧掉一个回合。

### 3. 新工具：`send_email`

隐式 TLS 的纯文本 SMTP 客户端，可在聊天里直接让 agent 发报告、提醒或摘要。
配置项 `smtpHost` / `smtpPort` / `smtpUsername` / `smtpPassword` / `smtpFromName`。

客户端暴露了一个**可注入的连接点**，因此它的命令顺序（`EHLO → AUTH LOGIN →
MAIL → RCPT → DATA → QUIT`）由单测覆盖，而不是假设正确——这正是移植代码时
最容易悄悄写错的地方。

### 4. 凭据加固

`client-config.json` 与 `account.json` 是运行时写到仓库根、内含微信 token 明文的
文件，现已加入 `.gitignore`。这两个文件**历史上从未被提交过**，补规则是为了避免
将来一次 `git add .` 就泄露。

## 升级须知

1. 拉取后 `pnpm build`（`lib/` 是提交进仓库的编译产物，`link:` 加载直接用它）。
2. **重启 `dsh web`** 才会加载新工具与新命令。
3. 想启用原生识图，先在 `settings.yaml` 里给路由模型声明 `inputModalities: [text, image]`，
   再重启；然后微信里发 `/识图` 确认模式与路由。
4. 若原配置里用了被归档的 `dsh-wechat-tools`（`send_email` / ESP32 灯控），
   邮件能力已内建到本 bundle，SMTP 配置迁到 `dsh-chatnode-wechat` 的配置下即可。

## 已知限制（未变）

- 出站语音/视频仍是**文件附件**（mp3/mp4），不是原生气泡——iLink 限制；
  `silk.ts` 与 `gateway.sendVoice()` 作为未启用的备用保留。
- 部分命令回执仍含 emoji，未与人设的禁 emoji 规则统一。
- `mediaDir/generated` 下生成的图片/语音暂无自动清理。
- 微信 `silk` 编码语音的 STT 待真机验证（m4a 已验证）。
- 仅面向一对一私聊；群聊按设计忽略。
