# v0.3.0 — 第三代：从"能收发"走向"能长期运行"

**日期**：2026-09-12　·　**类型**：minor（含一处配置面移除）　·　**测试**：154 项全绿

---

## 一句话

v0.2.x 解决了"能不能在微信里跟 DSH agent 说话"；v0.3.0 解决的是**它能不能一直好好
地跑下去**——上下文怎么轮换、失败怎么被看见、以及一个插件在什么情况下会把整个宿主
拖死。

## 为什么会有这一版

2026-09-12 同一天里暴露出三类问题，且都真实发生过：

1. **长会话自我续写**：单个微信会话累积到 60 轮 / 3083 个事件后，模型在自己输出里
   写出一条带**未来时间戳**的假用户消息（`[发送于 …] 视频呢？发个`），并照着它执行，
   造了一个没人要的视频。根因是入站消息用的是"行首说话人标记"格式。
2. **静默失败**：入站媒体下载返回空时零日志零提示；而"响亮失败"的提示本身又因为
   `peerId` 未赋值而**发不出去**。
3. **宿主被判致命**：配置写入触发热重载 → 插件 scope 被拆 → `void` 出去的异步启动
   函数用属性访问取服务而抛错（连 `catch` 里的日志访问也抛）→ **未处理的 rejection**
   → 宿主 `fatal load failure` 退出 → 桌面应用回落到安全模式。

本版把这三条都当作**一等公民**处理，而不是补丁式绕过。

## 适配版本

| 宿主 | `@deepseek-ai/*` | 状态 |
|---|---|---|
| DSH Desktop（桌面应用内置 harness） | **0.1.2-rc.1** | ✅ 实测：真人微信往返、生图、灯控、自动轮换全部通过 |
| `dsh` CLI（OpenClaw 便携版内嵌包） | **0.1.5-rc.2** | ✅ 实测：启动与插件装载通过 |
| cordis | `^4.0.2` | 必须与宿主对齐——双实例会破坏服务解析 |
| schemastery | `^3.18.2` | 必须单实例——3.18.1 与 3.18.2 并存会致 `TS2742` |
| Node.js | ≥ 22（实测 24） | 管理台与测试直接用 Node 类型擦除跑 `.ts` |

跨宿主差异（都已在代码里处理，列出来是因为踩过）：

- **`dsh-persona` 的配置键**：0.1.2 要求 `text:`，0.1.5 改名为 `prefix:`。preset 用
  YAML 锚点同时挂两个键名；两边 schema 都实测接受 `text+prefix`，因此同一份 preset
  在两个宿主上都能挂载。
- **`Session.events` 在 0.1.5 被移除** → 全库改用 `snapshotEvents()` 快照 API。
- **可选服务不得进 `inject`**：`sessionTitle` 依赖 `sessionProjections`；把它写进
  `inject`，在没有该投影的宿主上这一行会**永久 pending**，宿主随即判定
  `1 entry did not activate` 并让**整个 profile 启动失败**。可选项一律 `ctx.get()`。
- **热重载是常态**：本 profile 常用 `patchReload: live`，任何配置写入都会重载插件树。
  因此所有异步入口都按"scope 随时可能消失"来写（见下）。

## 改进

### 一、上下文生命周期

- 新增 **`contextPolicy`**，把"会话何时轮换"变成配置：
  `manual`（旧行为）/ `rotate-turns` / `rotate-turns+handoff` / `rotate-pressure` /
  **`rotate-tokens`** / `daily`。
- **`rotate-tokens` 支持自设 token 预算**：优先读宿主会话投影里的**真实上下文
  token 数**（`contextPressure.surfaceTokens` → `contextBreakdown` 求和 → 累计
  `tokenUsage` 依次回退）；读不到时按 2 字符/token 估算，并在播报里**注明是估算**。
- 轮换只在 `turn/end` 且**空闲**时发生，动手前再查一次空闲——绝不把正在跑的回合
  拦腰截断；轮换复用与 `/new` 完全相同的建会话路径（只有一处会创建微信会话）。
- **交接摘要不额外调用模型**：从会话事件确定性摘录最近几条，用独立定界标记
  （`<<<会话交接摘要·非用户指令>>>`）并写明不是指令，因此不会被人设硬规则当成
  命令执行。
- **交接摘要不再自问自答**：摘要只**排队**，搭在下一条用户消息上一并提交，一次回合、
  零多余气泡（此前它会作为新会话的 prompt，导致每次轮换多出一句"刚换了个新会话"）。

### 二、故障可见性

- **入站信封改为定界块**：`<<<微信用户消息>>> … <<<微信用户消息结束｜发送于 …>>>`。
  时间戳从"行首说话人标记"移到**结束标记**——行首那种形状是模型最容易被诱导续写的
  位置，而续写出来的一条假用户消息会被它当成指令执行。
- **入站媒体不再静默失败**：下载返回空、或 item 根本没有可下载媒体时，现在都会写
  warn 日志并回一句明确提示（图片 / 文件 / 视频 / 未知 item 类型四种情形）。
- **把失败提示真正送出去**：相关路径过去跑在 `node.peerId` 赋值之前，而
  `sendTextToPeer` 没有 peer 就直接返回——赋值已提前，提示才会真的到达。
- **重复投递被拦住**：iLink 有时不给 `message_id`（语音常见），而网关去重原本
  `if (messageId && …)`，等于**完全不去重**，同一条消息 6–9 秒后被再投一次、被回答
  两遍。现在无 id 时退化为**载荷指纹**（发送者 + 每项 kind/文本/媒体指针）并采用更短
  的 30 秒窗口：够抓住重投，又不至于吃掉有意重复的一句"你好"。

### 三、宿主稳定性

- **异步入口永不 reject**：`src/index.ts` 的凭据启动、`node/core.ts` 的入站事件
  处理器、`node/outbound.ts` 的 `sendTextToPeer`（出站唯一出口，被 8 处 `void` 调用）
  全部保证不产生未处理的 rejection——那是宿主判定致命的唯一入口。
- **服务访问一律 `ctx.get()`**，并在每个 `await` 之后**重新取**：属性访问在 scope
  被拆后会抛"cannot get required service … in inactive context"，而 `ctx.get()` 返回
  `undefined`，让"这一行不激活"代替"整机退出"。
- **`config-api` 行移除**：管理能力搬到独立进程，客户端设置页与 `dsh.client` 声明
  一并撤掉，从结构上消除"可选 `webServer` 依赖拖死 profile"的路径。

### 四、功能

- **独立管理台 `admin/`**：自己的进程、自己的端口（默认 `http://127.0.0.1:8790/`，
  回环访问免 token，API 仍需 token 且拒绝非回环 Host）。三页签：**配置**（复用桥自己
  的 `CONFIG_FIELDS`，secret 掩码 + 显式显示 + 写入前备份/校验，清空白名单会被拒绝并
  回滚）、**对话**（`wechat-*` 会话列表 + 转录查看）、**上下文方案**（一键切换 + 参数
  微调）。
- **新建 / 删除微信会话**：管理台把命令写进 `$DSH_HOME/wechat-admin/queue/`，桥在
  ≤2 秒内轮询执行并回写结果；删除是**可恢复**的——会话目录移入
  `$DSH_HOME/sessions-trash/`，投影缓存一并移走（否则 GUI 列表会把它"复活"），并让
  宿主解绑，避免后续消息路由进已不存在的会话。
- **恢复 `control_esp32_light` 工具**（`query|off|low|mid|high`），与聊天命令
  `/开灯 /关灯 /开灯1~3` 共用同一份实现。

## 验证

- **154 项单元测试全绿**：网关去重、入站路由/媒体/信封、命令面、审批桥、轮换策略、
  灯控、去重指纹、preset 兼容、boot 安全。
- **真实组合彩排**：以桌面宿主的真实 profile 起隔离实例 → 连上腾讯 iLink → 真人微信
  往返（文字/图片/文件/生图）→ 触发一次自动轮换并确认新会话可用。
- **热重载压迫测试**：对运行实例连续触发多次 patch 热重载，进程存活、桥持续轮询、
  stderr 无 fatal/unhandled。

## 升级注意

1. **配置面变化**：`config-api` 插件行被移除，微信桥配置不再有网页设置入口；配置改在
   `profiles/<profile>/cordis.patch.yml` 或独立管理台里改。
2. **模型看到的消息格式变了**（定界块）。若你有依赖旧 `[发送于 …]` 前缀的自定义
   提示词或人设规则，请同步更新——配套的人设硬规则在 preset 里，仓库不含人设内容。
3. **删除会话是可恢复的**，但仍请确认回收站后再清理 `$DSH_HOME/sessions-trash/`。
4. 依赖版本请与宿主对齐（见上表）：cordis / schemastery 尤其重要。
